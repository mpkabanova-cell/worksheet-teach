# Единый конструктор учебных материалов (по ТЗ аудита)

Работа идёт этапами внутри одного запуска. Каждый этап проверяется перед следующим. Дизайн, форма и блочный редактор сохраняются.

## Этап 1. Исправление ошибок из реестра
- B01–B03: при генерации показываются реальные этапы (план, задания, проверка, подготовка). Есть кнопка «Отменить», ограничение ожидания, понятная ошибка с кнопкой «Повторить». Параметры и созданные блоки сохраняются после обновления страницы. Повторное нажатие не запускает второй запрос.
- B04: предмет и класс передаются из формы в редактор при любом способе создания.
- B05/B06: «Добавить задание» и «Заменить это задание» — разные действия. Замена сохраняет место, уровень и баллы, а ещё даёт выбор: принять новую версию или вернуть старую. Если окно закрыть, работа продолжается в фоне, и её состояние видно.
- B07: ответ показывается один раз.
- B08/B09: незаданная сложность не выводится как «0 из 3». Уровень определяется по характеру действия.
- B10/B11: одно окно «Скачать / печать» вместо двух. Добавлен переключатель «Для ученика / Для учителя». Ученическая версия по умолчанию идёт без ответов.
- B12/B13: «Сделать интерактивным» заранее помечено как «скоро». Статус сохранения понятен, рядом есть кнопка «Сохранить».
- B14: после исправления проверим, что PDF и DOCX правда скачиваются. Сообщение об успехе появляется только после реального скачивания. Техническая фраза про «растр» убирается.
- U01: «Технический прогон» убирается из пользовательских режимов.

## Этап 2. Общая точка входа
- Форма переименовывается в «Создание материала», первым полем идёт «Тип материала»: Рабочий лист / Работа для проверки / Дифференцированные задания / Карточки и раздаточные материалы.
- Видны только настройки выбранного типа. Значения других типов при переключении не сбрасываются.
- Подписи на главной обновляются, в левое меню новые разделы не добавляются.

## Этап 3. Работа для проверки
- Вид работы (самостоятельная / проверочная / контрольная), время, число вариантов, проверяемые умения (с автоподсказкой и правкой), оценивание (без отметки / баллы и критерии).
- Сначала строится одна спецификация, по ней создаются все варианты. Варианты открываются вкладками над листом.
- Учительская версия: ответы, решения, баллы, частичный зачёт, таблица соответствия вариантов.

## Этап 4. Дифференцированные задания
- Вместо общей сложности выбираются уровни: базовый / повышенный / высокий. Задаётся число заданий на уровень, умение и форма выдачи (общий набор или отдельные комплекты).
- Уровни различаются видом мыслительного действия, а не размером чисел. Названия уровней ученикам по умолчанию не печатаются. Комплекты открываются вкладками.

## Этап 5. Карточки и раздаточные материалы
- Формат: карточка-задание / памятка / раздаточный материал. Назначение, число разных карточек, раскладка на A4 (авто / 2 / 4), форма работы (индивидуально / в паре / в группе).
- Каждая карточка — одна учебная задача. При печати карточки не разрываются, есть линии разреза, ответы идут отдельным листом.

## Этап 6. Проверка и удобство
- Числовые ответы с дробями проверяются точным вычислением, а не только словами модели.
- На узких экранах (360/390/768) видны лист и одна раскрываемая панель. Действия с заданием доступны без наведения мыши. У значков есть подписи.
- Прогоняем пункты приёмки из ТЗ: полный лист по тестовой теме, два варианта, три уровня, карточка, скачивание PDF/DOCX, восстановление после обновления.

## Технические детали
- Объект материала расширяется полями `materialType`, `modeParams`, `variants[]`/`levelSets[]`. У заданий появляются стабильный ID, умение, функция, уровень, ответ, решение, критерии, баллы и время. Старые черновики переносятся автоматически.
- Задачи генерации хранятся в localStorage со статусом этапа. Запросы к модели получают AbortController и таймаут. Если сервер отвечает ошибкой, клиент её показывает.
- Инструкции для модели: общая инструкция из ТЗ плюс правила выбранного режима (в aiPrompts/planAgentPrompt).
- Модуль проверки дробей на основе точной арифметики, с тестами. Тесты на правила приёмки: замена не меняет число блоков, добавление увеличивает на 1, в ученическом экспорте нет ответов, у вариантов совпадает спецификация.
- Экспорт: один модальный компонент. Аудитория версии передаётся в сборщики PDF и DOCX.
