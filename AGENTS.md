- The worksheet app (migrated Vite SPA) lives in src/App.tsx + src/screens|components|data|export and renders client-only from src/routes/index.tsx; it manages its own screens via state, so don't convert them to routes piecemeal. Why: it relies on window/localStorage everywhere.
- Server logic ported from Express lives in src/server-lib (plain JS) and is exposed via server routes /api/chat, /api/extract-context, /health, calling OpenRouter with OPENAI_API_KEY. Why: keeps the original AI provider and API contract the client already uses.
- PDF reading sends the whole file to a multimodal model instead of pdf-parse/canvas. Why: the server runtime cannot render PDF pages.
- Material types (worksheet / assessment / differentiated / cards) share one draft object and one editor; variants and levels are `draft.groups` + `block.groupId`, shown as tabs and generated by `src/data/materialGeneration.ts` on top of the worksheet generator. Why: the audit spec forbids separate editors per mode.
- Exports always go through `draftForExport` (student audience strips answers/solutions). Why: student files must never leak the key, even after teacher preview.
- Long AI runs go through `runGeneration` (stages, cancel, per-call timeout, soft time budget that skips optional repairs); unfinished runs persist in localStorage and the editor autosaves a draft. Why: generation used to hang with no way out.
- Assessment criteria rules and task numbering live in src/data/assessmentCriteria.ts: criteria must list every point level max→0 (ensureCriteriaLevels fills service defaults and flags needs-review), and exports number tasks via block.exportNumber set in draftForExport. Why: export numbering must match the platform per variant.
